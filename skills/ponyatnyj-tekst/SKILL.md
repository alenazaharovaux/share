# Понятный текст

Навык делает текст понятным человеку, который читает его впервые и не был в нашем разговоре. Правила собраны из комментариев автора навыка, Алёны, к реальным текстам. Каждое правило в `references/voprosy.md` взято из конкретного комментария, там же цитаты.

`humanizer-ru` не используется: он ищет внешние приметы ИИ-текста, а понятности не добавляет.

## Файлы навыка

- `references/voprosy.md` — вопросы читателя: по ним проверяется каждое предложение и абзац. Главный файл навыка.
- `references/primery.md` — пары «было → стало» из реальных текстов.
- `references/razbor-*.md` — разборы комментариев, из которых выросли правила.
- `scripts/check_text.py` — механический поиск подозрительных мест.
- `scripts/add_comments_to_html.py` — встраивает комментарии в готовую HTML-страницу и сохраняет её дизайн. Основной способ.
- `scripts/make_comment_page.py` — простая страница из .md без дизайна. Только для длинных md-документов, когда пользователь сам просит «из md».
- `scripts/read_comments.py` — комментарии из сохранённого файла в читаемый список.

## Режим «проверка текста»

### Шаг 1. Задача текста и читатель

До правки запиши для себя три вещи:
1. Задача текста одной фразой. Например: «Разобрать навык анализа интервью по шагам и объяснить, почему каждый шаг так устроен».
2. Читатель: кто он и что он уже знает. Например: «участник курса, исследователь, навык видит впервые, нашего разговора не видел».
3. Решения, которые приняли в разговоре и которые текст должен учесть. Например: «в навык добавляем страницу правок».

Каждый раздел текста сверяй с задачей. Раздел, который задачу не выполняет, переписывай или убирай.

### Шаг 2. Состав до разбора

Если текст описывает систему, процесс, документ или навык, в начале покажи его состав: из каких частей он состоит, что читает, куда пишет результат. Покажи таблицей, деревом файлов или схемой. Термин, который читатель видит впервые, объясни при первом упоминании.

### Шаг 3. Проход по предложениям

Читай каждое предложение отдельно, как будто соседних нет, и задавай вопросы из `references/voprosy.md`. Возник вопрос — перепиши предложение так, чтобы ответ был в нём самом. Главные вопросы:
- О ком или о чём это? Каждое «это, такой, другой, второй, его, тот» замени тем, на что оно указывает.
- Что значит это слово? Свой термин после большого перерыва назови полностью. Часть документа называй так, как она названа в самом документе.
- Откуда это известно? Ссылка на строку или источник — вместе с цитатой. Утверждение о системе — только после сверки с её файлом.
- Где это и куда? У глаголов «записывает, сохраняет, отмечает, кладёт» всегда есть место.
- Почему так? У правила и запрета — причина через последствие для результата.

Если два предложения держатся друг за друга и первое без второго непонятно, слей их в одно через двоеточие или придаточное. Фразы-анонсы вроде «по простой причине», «вот пример», «шаг нужен ради» удаляй и сразу пиши саму мысль.

### Шаг 4. Проход по абзацам

По каждому абзацу три проверки:
1. Можно ли по нему сделать слайд? Если в абзаце больше трёх правил подряд, сделай список или таблицу с примером на каждый пункт.
2. Есть ли пример? У правила, типа, категории — пример из одного сквозного кейса текста. Если кейса нет, выбери один и держи его через весь текст.
3. Понятно ли, зачем абзац здесь? Абзац, который не служит задаче текста, убери.

### Шаг 5. Проход по фактам

Каждую цифру, цитату, название, утверждение «навык делает X» сверь с файлом или источником в этой сессии. Цитату — со строкой источника. Если документ, на строки которого ссылается текст, читателю недоступен, приложи его.

### Шаг 6. Программа

```
python -I scripts/check_text.py <файл.md> [<отчёт.md>]
```

Программа находит подозрительные места: противопоставления «не X, а Y», слова-подпорки, предложения, которые начинаются с указательного слова, короткие предложения, которые могут быть непонятны без соседних, длинные предложения, номера строк без цитаты, сокращения без расшифровки. Каждую находку проверь глазами: программа ищет приметы, решение за тобой. Отчёт пишется в файл, в консоль — только число находок.

### Шаг 7. Сдача

Перечитай текст целиком последний раз как читатель из шага 1. Сверь с задачей и решениями из разговора. В отчёте пользователю перечисли, что поменял и почему, и предложи страницу для комментариев, если текст большой.

## Режим «комментарии»

Нужен, когда пользователь хочет надиктовать замечания к тексту голосом.

Режим включается и когда пользователь просит HTML: «подними HTML», «подними аштрейт», «апштрейм», «эйчтиэмэл» (так диктовка записывает слово HTML). Любую страницу, которую он просит поднять, делай страницей с комментариями.

Страница для пользователя — всегда страница с нормальным дизайном: карточки, колонки, метки, списки, отступы. Голые абзацы подряд с номерами автор навыка назвала «стеной текста» и «нечитаемо абсолютно» (10.11.2026). Слой комментариев добавляется поверх дизайна и ничего в нём не меняет.

1. Сначала сделай обычную HTML-страницу с дизайном: самостоятельный файл, `meta charset`, системные шрифты, ширина телефона без горизонтальной прокрутки. Положи её в папку «Загрузки» пользователя: `~/Downloads/<имя>.html`.
2. Встрой комментарии:
   ```
   python -I scripts/add_comments_to_html.py <страница.html>
   ```
   Готовая страница ляжет в `~/Downloads/kommentarii-<имя>-<дата-время>.html`. Комментировать можно каждый заголовок, абзац и пункт списка внутри `<main>`: выделить фразу или навести мышь и нажать «+ комментарий». Блок с комментарием обводится и получает счётчик. Кнопки «Комментарии: N» и «Сохранить комментарии» стоят внизу справа. Комментарии хранятся в браузере, «Сохранить комментарии» скачивает `.json` с тем же именем.
3. Проверь страницу в браузере сама до показа. Сделай скриншот и посмотри на дизайн: читается ли страница, не закрывают ли кнопки текст. Потом проверь комментарий: выделение, сохранение, перезагрузка. Расширение Chrome не открывает `file://`, поэтому для проверки подними временный сервер на копии страницы в рабочей папке сессии и выключи его по номеру процесса.
4. Открой пользователю страницу, дай путь к ней и жди «готово».
5. Найди файл комментариев сам: `kommentarii-<имя>-<дата-время>.json`, имя совпадает с именем страницы. Браузер кладёт его туда же, куда все скачивания. Ищи по порядку: «Загрузки» (`~/Downloads`), рабочий стол (`~/Desktop`), «Документы» (`~/Documents`), папки OneDrive в домашней папке, затем вся домашняя папка. Нашлось несколько файлов — бери самый новый. Путь спрашивай у пользователя, только если файла нигде нет. Прочитай комментарии:
   ```
   python -I scripts/read_comments.py <файл.json> <список.md>
   ```
   Открой `<список.md>` инструментом чтения файлов: консоль Windows портит кириллицу.
6. Разбери каждый комментарий: фрагмент, что сказал пользователь, какой вопрос возник у читателя, как исправить. Сгруппируй по видам вопросов из `references/voprosy.md`. Запиши разбор в `references/razbor-<ГГГГ-ММ>-<тема>.md`.
7. Исправь по всем комментариям исходную страницу с дизайном.
8. Новый вид вопроса, которого нет в `voprosy.md`, допиши туда с цитатой пользователя. Удачную пару «было → стало» допиши в `primery.md`.
9. Встрой комментарии в исправленную страницу для следующего круга и предложи её пользователю.

## Запрещено

- Вызывать или предлагать `humanizer-ru`.
- Рубить связную мысль на короткие предложения, которые без соседних непонятны.
- Ссылаться на то, чего читатель не видел: «второй вопрос», «этот журнал», «наша методичка» без объяснения.
- Ссылаться на строку или источник без цитаты.
- Писать о системе то, что не сверено с её файлами.
- Называть шаг проверки «переписать понятно»: шаг называется «проверка на понятность».
