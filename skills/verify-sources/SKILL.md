# Проверка источников без ручной сверки

Основа — эксперимент автора навыка, Алёны Захаровой, https://kinemetric.vercel.app/ (25.07.2026): шесть моделей писали обзор статей, у всех 60 ссылок из 60 живые, а одна модель выдумала всё содержание вокруг них и написала «всё проверено через PubMed», не открыв ни одного источника.

Три правила, которые из этого следуют:
- Живая ссылка ничего не доказывает. Проверяется связка «утверждение — цитата — источник».
- Слова «всё проверено» не считаются проверкой. Проверка — это файл, который можно открыть.
- Сверку делает отдельная новая сессия, которая сама открывает источники. Ревью «прочитай отчёт и оцени» выдумку пропускает.

Кабинетное исследование целиком (поиск, реестры, факты, синтез) ведёт соседний навык `desk-research`, правила — в его файле `references/method.md`. Этот навык — проверка: для готового отчёта или как шаг деска.

## Шаг 1. Правила на время ресёрча

Пока идёт поиск и пишется текст:

1. Каждое утверждение, число, дата и вывод — с источником. Отвергнутые источники тоже записываются, с причиной.
2. Каждое утверждение записывается в `claims.json` рядом с отчётом. Формат — `references/claims-format.md`. Поля: `id`, `claim` (утверждение как в тексте), `source` (ссылка) или `doi`, `quote` (дословная цитата из источника на языке источника), `location` (раздел, страница, таблица).
3. Число в утверждении пишется только если оно есть в цитате. Расчёт помечается «мой расчёт» и показывает, из чего посчитано.
4. Источник закрыт, платный или не открылся — так и пишется: «источник недоступен, не подтверждено». Похожие данные из другого места без пометки не подставляются.
5. Приоритет — первоисточникам: исследование, документ, отчёт компании. Пересказ в СМИ — только с пометкой.
6. Поисковый след: какие запросы, сколько результатов просмотрено, что взято и что отвергнуто с причиной.
7. Фраза «всё проверено» без файла `verification.md` не пишется.

## Шаг 2. Проверка программой

```
python <папка навыка>/scripts/verify_sources.py <путь>/claims.json
```

Программа открывает каждый источник, для DOI берёт метаданные из doi.org и аннотацию из Europe PMC. Если цитата по DOI не нашлась, второй проход берёт аннотации из OpenAlex, Crossref и Semantic Scholar. Программа ищет каждую цитату в тексте источника и проверяет, что каждое число из утверждения есть и в цитате, и в источнике. Итог — `verification.md` и `verification.json` рядом с `claims.json`. В `verification.md` списки:
- подтверждено;
- подтверждено частично (цитата найдена с расхождениями в словах);
- число не подтверждено;
- цитата не найдена в источнике;
- нет в аннотации, полный текст не прочитан (DOI, страница издателя не открылась) — сверить по полному тексту;
- источник не прочитан программой (PDF, 403 от защиты от роботов, сеть);
- число из файла (утверждение с полем `data`: таблица, xlsx, выгрузка) — сверить по сохранённому файлу;
- DOI не существует;
- без источника или без цитаты.

Нужен интернет. В Codex в обычном режиме интернет для команд выключен, и программа не откроет ни одного источника: все утверждения попадут в «не прочитан». Включить один раз в `~/.codex/config.toml`:

```toml
[sandbox_workspace_write]
network_access = true
```

Проверено 08.10.2026 в Codex 0.161: без этой строки 0 подтверждённых из 33, с ней — 29 из 33 за полминуты. Веб-поиск самого агента от этой настройки не зависит.

После программы:
- «Цитата не найдена» и «число не подтверждено» — исправить текст отчёта по источнику или убрать утверждение. Потом запустить программу снова.
- Отчёт отдаётся только вместе с `verification.md`.

## Шаг 3. Сверка новой сессией

Запускается в новом чате, отдельно от сессии, которая писала отчёт. Промпт:

```
Возьми отчёт <путь>, claims.json и verification.md. Открой сам каждый источник из списков «подтверждено частично», «число не подтверждено», «цитата не найдена», «нет в аннотации», «источник не прочитан» и «число из файла» и сверь с ним утверждение. Числа из файлов сверяй по сохранённым файлам. Не оценивай отчёт по тому, как он написан, и не полагайся на то, что в нём заявлено проверенным.

Выдай три списка в файл review.md рядом с отчётом:
— утверждения, которые совпали с источником;
— утверждения, которые не совпали, с текстом отчёта и текстом источника рядом;
— утверждения, источник которых открыть не удалось.
```

Формулировка «открой источники сам» обязательна.

## Признаки имитации

Из эксперимента KINEMETRIC. В каждой паре числа должны совпасть:
- число источников, на которые ссылается отчёт, и число источников в `claims.json`;
- число запросов, заявленное в отчёте или поисковом следе, и число вызовов поиска в логе сессии или в итоге агента;
- число источников в `claims.json` и число источников, которые программа открыла, плюс помеченные «недоступен».

Первую и третью пару считает `<папка навыков>/desk-research/scripts/check_counts.py <папка с claims.json> <файл отчёта>`. Вторую сверяет человек. Расхождение — назвать пользователю.

## Что считать готовым
- `claims.json`, `verification.md` и `review.md` лежат рядом с отчётом.
- В отчёте нет утверждений из списков «не найдена» и «не подтверждено», кроме помеченных как неподтверждённые.
- Скриншот, если результат — страница или презентация: проверка кодом вёрстку не ловит.
