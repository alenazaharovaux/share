# Кабинетное исследование

Правила — в файле метода `references/method.md` в папке этого навыка. Прочитай его целиком до шага 1. Если правило навыка расходится с файлом метода, прав файл метода.

Проверку цитат делает программа соседнего навыка `verify-sources`: `<папка навыков>/verify-sources/scripts/verify_sources.py`. Папка навыков — та, где лежит этот навык, обычно `~/.claude/skills/`.

Общайся с пользователем на его языке. Навык написан на русском, правила от языка не зависят.

Файлы навыка:
- `references/method.md` — файл метода: уровни источников, открытые данные, поиск, сила вывода;
- `references/registry-format.md` — реестр источников и поисковый след;
- `references/raw-format.md` — файл фактов;
- `references/agent-prompts.md` — промпты агентам и промпт сверки;
- `scripts/raw_to_claims.py` — файл фактов → `claims.json`;
- `scripts/check_counts.py` — признаки имитации.

## Шаг 0. Настройка при первом запуске

1. Проверь, что рядом лежит навык `verify-sources`: файл `<папка навыков>/verify-sources/scripts/verify_sources.py`. Нет — скажи пользователю: «Навык desk-research работает только вместе с verify-sources. Установи его из того же репозитория в ту же папку навыков». Дальше шага 0 не иди.
2. Проверь Python: `python --version` (или `python3`). Нужен Python 3.8 и новее. Сторонние библиотеки не нужны.
3. Прочитай `config.md` в папке этого навыка. Есть — переходи к шагу 1.
4. Нет — задай вопросы ниже по одному. Любой можно пропустить ответом «пропустить».

| Вопрос | Ключ в config.md | Если пропустили |
|---|---|---|
| В какой папке лежат твои проекты? Деск кладётся в папку `desk/` внутри проекта. | `projects_folder` | Каждый раз спрашивать, куда класть деск |
| Где искать прошлые дески, чтобы не делать работу дважды? Можно несколько папок через запятую. | `past_desks` | Искать в `projects_folder`; нет и его — пропустить поиск прошлых десков |
| Есть ли у проекта файл-карточка, куда дописывать строку о сделанном деске? Например `README.md` в папке проекта. | `project_card` | Строку в карточку не писать |
| Какие поисковые сервисы у тебя подключены: Exa, Consensus, papers? | `search_tools` | Проверять на шаге 2 и работать с тем, что есть, плюс обычный веб-поиск |

5. Запиши ответы в `config.md` в папке навыка:
```
projects_folder: ~/Projects
past_desks: ~/Projects, ~/Archive
project_card: README.md
search_tools: exa, papers
```

Дальше «пользователь» — тот, кто запустил навык.

## Где лежат файлы

- Деск по проекту: папка `desk/` в папке проекта из `projects_folder`. Справка внутри проекта: `desk/spravka-<тема>/`.
- Без проекта: спроси пользователя, куда класть.

Полный деск:
```
desk/
  plan.md              рамки и план поиска
  sources/             реестры 0N-istochniki.md, data/, snapshots/
  _raw/                файлы фактов 0N-fakty.md
  claims.json, verification.md, verification.json, review.md
  0N-<блок>.md         выводы по блокам
  00-vyvody.md         общий итог
```

Справка:
```
desk/spravka-<тема>/
  fakty.md, claims.json, verification.md, spravka.md
```

## Шаг 1. Вопрос, рамки и режим

1. Запиши решение, под которое ищем, и кто его принимает.
2. Разбей на блоки. У каждого блока номер, вопрос и тип вопроса: «влияет ли X на Y», «насколько распространено», «что делает компания», «что говорят пользователи».
3. Критерии включения: период, страны, отрасль, язык, типы источников.
4. Что считаем ответом: число, перечень, механизм, пример.
5. Инструменты по теме, обязательного нет. Веб, книги, отчёты, компании, гуманитарные темы — Exa. Научные статьи — papers (бесплатно). Доказательная наука с фильтром по метаанализам — Consensus. Нет ни одного из них — обычный веб-поиск агента. Список — в файле метода, раздел «Поиск».
6. Потолок: сколько прогонов агентов и сколько денег на платные сервисы. Перед запуском напиши пользователю одной строкой «≈N запросов, примерно $X» и жди «да».
7. Режим. Один вопрос → быстрая справка. Несколько блоков или результат идёт заказчику → полный деск.
8. Проверь сама, есть ли деск на эту тему в папках из `past_desks`: папки `desk/`, их `00-vyvody.md` и реестры. Покажи пользователю, что нашла: путь и одну строку о том, про что деск. Ничего не нашла — так и скажи. Затем спроси, что из найденного включить в текущий деск и есть ли источники, которые пользователь или заказчик уже знают.
9. Место деска выбери сама по разделу «Где лежат файлы».

Полный деск: запиши всё в `desk/plan.md` и покажи пользователю. **СТОП** до его «ок».
Справка: коротко покажи вопрос, тип, критерии и потолок в чате и переходи к шагу 3 после «ок».

## Шаг 2. План поиска (полный деск)

Для каждого блока допиши в `plan.md`:
- запросы на русском и английском;
- запросы от обратного для поиска опровержений;
- какие инструменты для блока, по правилу из шага 1, и какие источники открытых данных из файла метода;
- сколько агентов и волн. Агентов запускай волнами по 3–4.

Проверь инструменты до запуска: Exa, Consensus, papers. Не подключён нужный — скажи пользователю, что именно, и спроси, идём без него или ждём.

## Шаг 3. Реестры источников (полный деск)

1. Запусти поисковиков по промпту 1 из `references/agent-prompts.md`, по одному на блок.
2. Каждому агенту: не запускать своих агентов. После запуска проверь список фоновых задач. Видишь второй агент с похожим заданием — останови его.
3. Когда агент вернулся, открой реестр и проверь:
   - формат по `registry-format.md`;
   - у каждого источника уровень и доступ;
   - есть раздел «Опровержения» и раздел «Остановка»;
   - открой 2–3 случайные ссылки. Ведёт на пересказ при доступном первоисточнике — замени первоисточником и проверь остальные ссылки агента целиком.
4. Сведи реестры: дубли, пробелы, блоки без источников первых двух уровней.
5. Покажи пользователю сводку: по блокам число источников по уровням, источники «против», что не нашли. **СТОП.** Пользователь утверждает реестры, может добавить источник или подключить свой доступ.

## Шаг 4. Сбор фактов

**Полный деск.** Запусти сборщиков по промпту 2, только по утверждённым реестрам. Блок с большим реестром дели между 2–3 агентами по строкам. Когда агент вернулся, проверь формат файла фактов по `raw-format.md` на 10 случайных строках.

**Справка.** Запусти одного агента по промпту 3. Он ищет и собирает факты сразу в `fakty.md`.

## Шаг 5. Проверка программой

```
python <папка навыков>/desk-research/scripts/raw_to_claims.py <папка desk или справки>
python <папка навыков>/verify-sources/scripts/verify_sources.py <папка>/claims.json
```

1. `raw_to_claims.py` печатает строки, которые не разобрал, и номера источников, которых нет в реестре. Поправь их в файле фактов и запусти снова, пока список не станет пустым.
2. `verify_sources.py` пишет `verification.md` и `verification.json`. Без интернета программа ничего не откроет. В Codex интернет для команд включается в `~/.codex/config.toml` (см. навык `verify-sources`).
3. «Цитата не найдена» и «число не подтверждено» — найди верную цитату в источнике или поставь строке пометку «не подтверждено». Запусти обе программы снова.
4. Авторов научных статей, которые войдут в выводы, проверь по PubMed или OpenAlex.

## Шаг 6. Сверка новой сессией

- Полный деск: сверка всего, что программа не подтвердила, и всех строк «данные».
- Справка: сверка только того, что программа не подтвердила. Если подтверждено всё и строк «данные» нет, шаг пропускается.

Сверку делает субагент с чистым контекстом или новый чат. Он не видит переписку, ход поиска и рассуждения агента-поисковика, сам открывает источники и пишет `review.md`.
- Субагент: запусти `general-purpose` с промптом 4 из `references/agent-prompts.md` дословно. Подставь только пути. Свои догадки о причинах расхождений, оценки и пояснения в промпт не добавляй. `review.md` не правь.
- Новый чат: дай пользователю тот же промпт 4 с подставленными путями.

**СТОП** до появления `review.md`.

Когда `review.md` есть: «не совпали» — исправь факт по тексту источника или поставь «не подтверждено». «Открыть не удалось» — «не подтверждено».

## Шаг 7. Синтез

Пиши сам, в основном чате. Агентам синтез не отдавай.

1. По каждому блоку — `desk/0N-<блок>.md`. В справке — `spravka.md`.
2. У каждого утверждения ссылка на источник. Используй только факты, подтверждённые программой или сверкой.
3. У каждого вывода сила A, B или C по правилам файла метода. Вывод только по аннотациям — не выше B. Есть источники «против» — не выше B, и они стоят рядом с выводом.
4. Где данных нет — «данных не нашли» и что искали.
5. В справке — раздел «Что не искали».
6. Полный деск: `00-vyvody.md` — общий итог по блокам и список пробелов: чего не нашли и у кого запросить.

## Шаг 8. Признаки имитации и сдача

```
python <папка навыков>/desk-research/scripts/check_counts.py <папка> <файлы выводов>
```

1. Пара 1: источники в выводах, которых нет в `claims.json`, — у утверждения нет проверенной цитаты. Убери его или добавь факт и проверь.
2. Пара 2: источники, которые не открылись и не помечены «недоступен», — открой руками или поставь пометку.
3. Пара 3: сравни число запросов в поисковом следе с числом вызовов поиска в итоге агента, если среда его показывает. Сильное расхождение — назови пользователю.
4. Результат — страница или презентация: посмотри скриншот.

## Что считать готовым

- [ ] Есть выводы, у каждого утверждения ссылка, у каждого вывода сила A/B/C.
- [ ] Источники «против» показаны рядом с выводами.
- [ ] Есть `claims.json` и `verification.md`. В полном деске и при неподтверждённом в справке — `review.md`.
- [ ] Строки «не найдена» и «не подтверждено» в выводы не попали.
- [ ] `check_counts.py` прошёл без расхождений или расхождения названы пользователю.
- [ ] Поисковый след записан. Полный деск — реестры утверждены пользователем.
- [ ] Список пробелов: чего не нашли, что не искали, у кого запросить.
- [ ] Если в `config.md` задан `project_card`: в карточке проекта строка `- [ГГГГ-ММ-ДД] деск | <что сделано>`.

Назови пользователю пути к выводам и к `verification.md`, сколько утверждений подтверждено и сколько нет. Без файла проверки фразу «всё проверено» не пиши.
